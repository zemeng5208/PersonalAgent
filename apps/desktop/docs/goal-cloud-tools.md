# Desktop Goal cloud tools

This Desktop adapter exposes the existing Goal commands to the `huawei_ict_agentarts` Competition Profile. It does not add a graph, task runner, or cloud fallback.

`createDesktopGoalCloudHost({goalHost})` accepts the existing bound Goal host and returns `tools`, `competitionToolAvailability`, `competitionToolExports`, `snapshot()`, `bindApplication(application)`, `authorize({goalCloudConsent:true})`, `revoke()`, `assertCloudSend(request)`, and `close()`. Bind the Goal host to the Runtime application first, then bind this adapter. Register the adapter's four tools instead of registering the original write tools a second time. Add its availability and export bindings to the Competition catalog, and call `assertCloudSend` from the trusted `beforeCompetitionSend` hook. Renderer only invokes trusted Desktop authorization IPC; it never supplies a graph namespace or source reference.

The tool names are `goals.create`, `goals.revise`, `goals.list`, and `goals.get`. Create and revise use the public Goal tool implementation, including graph revision and goal revision checks. `sourceRef` is optional in the registered input schema so existing local Goal host commands remain valid. A cloud proposal containing `sourceRef` is rejected; Desktop supplies a task and run bound value after that check. A local host command may keep its original value only when the persisted host tool intent, exact arguments, command ID, conversation, run ID, and allowed Runtime approval all match. Runtime Policy and ToolGateway still decide write approval, execute the operation, and record its result. The read tools return current goal fields and revisions so a later revise can supply both exact expected revisions. Lists contain at most 20 goals per page.

The adapter starts closed. Explicit session consent enables goal content in this conversation to be offered to AgentArts. Only `desktop-panel` and `desktop-workspace` tasks can claim the grant. A task's persisted grant generation cannot be reused after revocation, renewal, or a Desktop restart. The final cloud send guard rejects an old selected catalog or continuation after revocation. The host must call that guard on every AgentArts request; catalog registration alone is insufficient.

Cloud projections contain goal ID, revision, summary, validity, sensitivity, state, reason, graph revision, and minimal write receipts. They omit source references, dependencies, raw graph snapshots, Fact content, credentials, and absolute paths. Restricted goals and goals with path or credential markers are withheld from list/get and cannot be revised through this adapter. Goal write proposals with restricted sensitivity or unsafe text are rejected. A goal tool result cannot be exported after its current goal has become restricted or changed revision.

Desktop Main registers these tools in the production Competition catalog, binds the adapter after the original Goal host, and checks the grant on every cloud request. Settings → connections offers session authorization and revocation. The existing local Goal editor remains usable without this cloud grant. AgentArts and Live credential storage are unchanged.

The dedicated test uses the public Goal commands and a real local Runtime store to cover create, list, get, revise, stale revision rejection, restricted data filtering, consent revocation, and an approved local host write without cloud consent. The two directed tests passed in the adapter worktree. Integration checks passed Runtime compilation, syntax checks for changed Desktop files, and an isolated rendering check of the settings section. These checks do not establish real AgentArts or Electron acceptance.
