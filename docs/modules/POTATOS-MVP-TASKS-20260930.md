## 4. P1-A：日历正式来源与变化读回——优先解除主动决策依赖

### 当前事实与复用入口

- #216 已交付 `@personal-agent/calendar` 的 `ICalSubscriptionProvider`。#226 的 CalDAV 是只读增量工作包，不是已验证的写日历能力。
- 你已在 #212 确认 `CalendarService.listEvents(accountRef, window, paging)`、`getEventItem(accountRef, externalId)`、`searchEvents(accountRef, query)` 为公开服务入口；Runtime/ConnectorHost 工厂尚需对接。
- `ConnectorItem` 的 `source='calendar'`、`externalId` 是 UID、`occurredAt` 是开始时间，`dedupeKey` 含 `calendarId/externalId/sequence`。它没有独立 `sourceRevision`，不能让消费者猜一个不存在的字段。
- 已知 iCal 列表会过滤 cancelled；取消需要对已知 UID 使用单条读回。`NOT_FOUND` 与明确取消不是同一事实。

### 需要完成

1. 交付现有提供者的正式构造、注册、连接/释放及能力发现规格，明确实际支持 iCal/CalDAV 的账号类型、只读边界、认证方式和工具版本。不要保留把真实提供者标为 fixture/mock 的过时示例。
2. 和 goo122 确认受信 ConnectorHost 工厂/凭据端口；和 P8 提供唯一挂载参数与补丁位置。你实现连接器及其专属适配，不等待别人替你定义业务能力，也不直接双写共享 main.js。
3. 支持窗口分页及单事件正式读回。说明 revision 来自 `sequence`、`updatedUtc` 或 CalDAV ETag 的哪一项，比较规则、缺失行为、删除与取消区别必须可复现。
4. 给 P5 一份可消费字段映射：稳定 UID、来源、版本、获取时间、UTC 开始/结束、当地墙上时间与时区、status、引用/出处。这是现有类型到消费端口的映射，不私建公共 wire DTO。
5. 已知 UID 的取消/撤回读回不能因列表过滤或缓存一直不可见；更新和未变更的实际数据路径分别说明。旧新事件差异与 `MeetingRescheduleEvent` 语义由 P5 生成。
6. 核对 TZID、floating time、全天事件、重复事件和 DST 支持范围；不支持的情况明确拒绝或标记限制，不能静默把当地时间当 UTC。修有实际错误的路径，不为本轮实现整个 RFC。
7. 至少一个真实可用来源完成读取和一次确有版本依据的变化/取消读回；没有前版本的首次读取不称“发现变化”。私人日历的出机范围需要既有授权。
8. 只读提供者缺 `respond`/写入能力时返回不支持，不能模拟会议已改期。首版若需要外部日历写动作，明确列对应提供者及授权依赖，由协调方决定，不隐藏在只读验收里。

### 完成标准

正式来源 → 公共连接器/工具 → 受信宿主 → P5 实际获取可比较事实。连接器层给真实版本/时区/状态读回证据，P8 接通用户查询入口，P5 负责之后的多候选决策。Fake、公开测试来源和私人账号验收分别标明。

## 10. 与新增 AgentArts 工作流及低延迟设计对接

用户新增要求：增加实用工作流、优化设计、提高平台参与程度，并降低大模型和整体交互延迟，争取接近 GPT 的体验。线上 AgentArts 的编辑、发布和 runtime 绑定由 zemeng 侧唯一写入，你提供云端可消费的正式能力。

- 给出轻量工具目录：名称/版本/Schema/副作用/需要的 scope、可用性、deadline/cancel、结果投影和错误语义。不要让每轮云请求携带全部源码、历史或私人原始对象。
- 同类连接器用可复用工具子流程；可确定的选择在平台已支持的条件路由解决，避免每个连接器再堆串行 LLM。独立读取若允许并行，注明资源和外部限流条件。
- 公共读取缓存必须带版本/获取时间/有效期/来源，不能用过期私人或撤销信息换低延迟。
- 结果投影包含云回答所需最小事实和引用；敏感信头/路径只在已有出机范围内脱敏投影，authorizationRef/凭据不出机。
- 主对话/Live 在请求后展示真实有效输出或 Runtime 执行状态；TTFT/首个有用内容、整轮耗时、工具耗时、模型调用次数分别测，不能用快速占位文字冒充回答快。
- 当前旧报告 31.1s/8.5s 只能称请求完成间隔，不是 TTFT、header latency 或冷启动证据。达不到目标如实说明具体瓶颈，不保证未测过的 GPT 等效时延。
- 平台新增好用功能可由云端负责人核实后接入；不要为此擅自订购新套餐、改云租户或替代本地可信执行边界。
