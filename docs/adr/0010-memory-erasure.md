# ADR-0010：记忆物理删除与派生投影清理

- 状态：proposed；在实现和对外公布删除能力前需非作者评审。
- Profile：`huawei_ict_agentarts`；关联 PA-020、PA-024、MOD-09。
- 产品选择：用户要求删除时，清除选定事实的历史版本及派生索引；逻辑撤回不能冒充删除。

## 现状与约束

Memory SQLite 保存事实历史、公开来源映射、查询快照、feed 批次和确认回执。Runtime SQLite
另存图谱完整历史、精确 FactRef 投影、暂存批次、影响与回执。两库没有跨库事务。单独执行
`DELETE FROM memory_facts` 会留下可读的派生内容，也会让旧批次和图谱引用失去来源。

删除以受信宿主选定的 memory namespace 和稳定 fact ID 为边界。请求必须绑定当前头版本、
一次性授权和不含事实正文的操作 ID。来源检索失败、模型建议或普通撤回都不能触发删除。
现有读写端口不授予删除权限；在完整闭环验收前不得新增 wire capability。

## 方案与顺序

无下游 feed 绑定的事实可先走 Memory 单库快路径：以当前头 revision 为 CAS 前提，在一个
事务中删除全部版本及公开来源映射，废弃含目标的查询快照，并保留不含正文的 ID 删除标记。
只要该 namespace 曾绑定 feed，
快路径就拒绝；这不证明来源已停止重新导入，也不提供完整的用户删除能力。

1. 先在持久日志记录删除意图，并使该事实对查询、feed 和新的投影不可见。重启时从日志
   继续；重复操作 ID 只读取既有状态，不能以新的参数复用。
2. 在 Runtime 事务内清理目标事实的图谱版本和依赖它的派生节点、精确投影、暂存批次、
   影响与回执。无关节点须保留并通过图谱校验；旧图 revision、游标和引用不得被悄悄重用。
3. Runtime 清理回执持久化后，才在 Memory 事务中移除事实历史和来源映射。只移除
   含目标内容的查询快照与交付条目；混合交付中的无关条目、绑定及检查点继续有效。
   不能在清理下游前先丢失唯一来源。
4. 两库读回均确认无目标内容后，完成不含事实正文的删除回执。中途失败保持不可见并
   等待对账；不报告已删除，也不自动恢复旧内容。

Runtime 已有纯函数试验：按显式依赖边传递删除节点的全部版本，重排 graphRevision，
再用 `parseGraph` 验证幸存历史。它尚未接入持久库。没有依赖来源标记的自由文本复述
无法靠该算法可靠识别；接入完整删除前须建立来源追踪和存量记录核查，否则不得宣称
派生内容已全部清除。

Memory 当前已实现持久待删意图：在同一事务中隐藏目标事实，逐条改写 feed 交付和
bootstrap 偏移，并只废弃实际含目标事实的查询快照；旧批次内容不能再次确认。
Runtime 在消费前读取同一批次的最新交付，将待确认或已确认但未激活的混合暂存原子改写为
幸存事实后再投影；非法重写保留原暂存。目标事实、来源映射和已激活 Runtime 投影此时
仍存在，因此 `pending` 不能返回删除完成。
Runtime 已激活的旧投影回执仅保存批次哈希和链接。Memory 可按原 token 读出改写后的
交付，但尚未逐条核对每个旧回执都有可用交付及幸存 FactVersion；缺任一输入时必须拒绝。
图谱压缩还会改变历史 revision、影响报告和外部游标。处理这些记录前必须有可验证的
回执重算与游标迁移规则；旧回执无法无损重写时拒绝完成删除，不清空整个批次。

## 混合批次的保留门槛

一个 feed batch、Runtime 暂存或影响回执可以同时包含目标事实和无关事实。不能为删除
目标事实而直接删除整条混合批次，也不能清空整个 namespace 的交付与绑定；这会丢掉
无关事实尚未完成的消费。实施前须用合成混合批次证明以下原子重写或明确拒绝删除：

- 待确认交付只移除目标 FactRef，保持其余条目的顺序、来源事件和原检查点；同步修正
  bootstrap 偏移与待交付内容。持有旧批次内容的调用必须失败并重新读取。
- 已确认交付和 Runtime 投影回执只擦除目标引用；其他事实的映射、完成状态和待处理影响
  必须仍可读、可重试。不得通过删除整个回执掩盖未处理的无关影响。
- 只废弃实际含目标事实或其来源引用的查询快照；无关分页继续可用。新查询、历史、
  精确读取和 feed 均不得重新返回待删事实。
- 在 Memory 与 Runtime 的提交边界注入中断，并用读回核验不丢无关事件、不重复外部
  副作用。若无法证明混合批次可重写，保持删除请求待对账，不报告完成。

SQLite 活动库须验证 WAL、释放页和备份副本的处理方式。仓库当前没有统一备份生命周期，
因此在该策略和真实宿主授权接入前，不宣称私人数据已经被彻底清除。

## 兼容与验收

首片只使用受信宿主 API，不改现有 `MemoryQueryPort`、`FactChangeFeedPort` 或 wire 版本。
既有 `withdrawPublicSource` 继续表示可追溯撤回，不改变为物理删除。完成门槛包括：

- 合成事实多版本及修订后删除；当前、历史、精确引用和旧快照均不可读；
- 已投影事实及依赖链清除，独立 Goal/Plan 和其他 namespace 原样保留；
- 在两库每个提交边界注入中断，重启后续做且无重复副作用；
- 取消、过期、旧 revision、重复操作 ID、越权与仍有未确认交付时 fail closed；
- 新旧 SQLite 迁移保留未删数据，完成后检查活动库与派生索引的实际读回。

上述门槛未满足时，MOD-09 继续为 `in_progress`，接口仍为 `provisional` 或
`unavailable`；离线 Fake 不能替代真实私人来源、Desktop 授权和备份清理验收。
