# ADR-0033：镜像内编码最小修复与 F15 多轮工作流

- 日期：2026-10-17。
- 状态：实施中，接口 provisional；不是模型或整体架构最终定案。
- 授权：Owner 本轮要求“最小修复一并做了”，并明确算法与工作流都进入自有镜像。此前这部分暂停被本轮授权取代；不据此恢复其他未授权算法或宣称全部28图完成。

## 决定与边界

扩展原 `OwnedWorkflowEngine` 的 F15，不另建任务库、Agent 执行器或调度器。云端镜像负责失败分析、候选增量补丁及图控制；原本机 Runtime/Policy/ToolGateway 执行受信工具、管理审批与任务、持久化真实 Evidence。Renderer 不执行该循环。

新 `codingRepair` v1 进程/工具数据契约独立于 Core wire，覆盖任务隔离 session、文件与配置指纹、workspace 生产依赖图、检查配方、当前验证状态、精确补丁与交付读回。解析成功、签名通过和模型回答均不授予权限，也不证明业务成功。旧 F15 输入与原调用继续兼容。

## 算法与工作流

1. 捕获目标内和目标外已有用户修改的基线。在任务隔离目录工作；依赖和构建产物不得通过可写链接反向污染用户目录。
2. 真实读取当前文件、检查输出和版本。根据诊断及包依赖闭包圈定需重查范围；没有新证据不凭模型自述创造来源。
3. 由既有模型入口生成增量候选，使用 `diff@8.0.4` 计算实际 hunk、增删与范围；`typescript@5.9.3` 对 JS/TS 给出语法和包围声明资料。其他语言不冒充已有 AST 支持，可继续使用宿主真实公布的检查配方。
4. 将候选按当前 SHA 与唯一精确文本匹配预览、审查并应用到隔离根。jsdiff 仅用于分析，不用它的偏移/模糊 apply 替换可信写入器。小改动不自动等于语义正确，不能通过删除断言或变更检查配方制造通过。
5. 记录实际命令、退出码、日志诊断及其输入指纹。只有已确认的检查失败能触发重读和下一轮修复；unknown、stopping、未读回写入继续核实原操作。
6. 修改包内源码、测试或配置时，该包及其下游消费者验证状态变 STALE；根锁文件/构建配置或不完整依赖信息按保守影响处理。历史 Evidence 保留，只派生当前 VALID/STALE/FAILED/UNKNOWN 状态。
7. 下一轮继续相同 F15 图，封存 round、失败/源码/补丁摘要与历史操作；新 operationId 绑定轮次和版本。相同源码、相同失败和相同补丁再次出现时停止无进展重判；沿用原任务期限与宿主预算，不擅自另设固定轮次。
8. 所有必选检查在当前代码下 VALID、执行已停止且没有未知写入后，才交付候选。逐文件核对用户主目录仍等于启动基线，再走既有锁内 CAS 和写后读回；冲突不覆盖运行期间的新用户修改。

多文件交付必须保留 journal 及逐项读回。它不是多文件断电原子事务；部分已发生写入不能被隐去、盲重试或盲回滚。取消/超时发生在隔离工作区时，不需要更改用户主目录。

## 影子、传输和兼容

主图与独立隔离影子拥有不同任务、会话、操作和目录。影子可生成和验证补丁，不能自行发布到用户主目录或消费主分支授权；比较和准入沿用既有策略，不将双案例当成日常机会影子已验。

继续使用固定版本 AgentArts WSS 与显式 HTTPS 备用。工作流 JSON 经原传输承载，沿用当前结果字节预算和 unknown 语义；不能将已 accepted 的未知写入换通道重发。宿主签名优先复用既有可信密钥派生/提供端口，不进入 Renderer、提示词或公开日志。

任务目录隔离与受控路径工具保护正常任务的用户基线；现有 Job Object 管进程树，不是阻止任意恶意项目脚本访问同账号其他文件的 OS 文件系统沙箱。缺少的能力如实公布，不凭目录名称声称完整安全隔离。

## 复用与成本

[jsdiff 8.0.4](https://github.com/kpdecker/jsdiff/tree/v8.0.4) 和 [TypeScript Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API) 在实际消费包显式声明为精确生产依赖；它们此前只是传递/开发依赖，不能算已进入旧镜像。新 allowlist 导出递归带入依赖，沿华为 npm 镜像获取并保留锁定完整性。无新增模型、数据库或后台模型线程；不引入整套新的编排框架。

最小性是可测的改动范围及验证约束，不保证全局最优补丁。实际行为正确性继续依赖真实检查、来源和独立审查。

## 验收与迁移

必须经过生产 F15 advance 逐节点验收：读取 → 首次修改 → 真实检查失败 → 重读与增量修复 → 检查通过 → 当前指纹有效 → CAS 交付。至少覆盖两个不同文件布局的项目、dirty 用户基线、配置/下游 STALE、取消、并发冲突、未知写入、SQLite 重启、隔离影子及每阶段耗时。

显式 Fake 模型验证控制流，真实本机文件/检查验证执行，精确云版本与真实模型另验；不能用 model_turn、手工 runAgent、目录或模型自报代替。实现、代码检查、PR 集成、镜像构建、SWR 上传、平台部署和真实整图分别记录。
