## 实施规则

本轮优先实现类似“贾维斯”的主动能力：真实 Fact/Goal 与 Windows 指标变化产生影响判断、
去重提醒、可审查的最小计划修复；副作用仍须对应授权。Live 双方发言与文字一起持久保存，
普通回答结束后继续聆听，用户关闭才结束主动会话；连接异常需给出明确原因。

邮件、订阅与社交变化须通过现有连接器形成带来源的事实，传播到受影响目标、决策与计划。
Laya 在已授权范围内自主完成简单低风险分类与决策，Agent 汇总重点与处理结果；
需要审批或超出权限的动作继续经过 Policy。千封批处理等场景须实测吞吐和时延，不能预先承诺。

2026-09-27 交互补充：文字输入只用文字回答；Live 直接用实时语音回答。默认 F8
全局快捷键切换 Live，可修改。一个主对话统筹，展开显示子任务对话、模型、思考
深度、状态和结果；模型参数须真正应用。千问只承担 Live 交互，业务工作沿用
AgentArts 与同一 Runtime/Policy/工具体系。用户已明确授权阿里云 Live 音频与上下文。

1. 先核对平台和仓库已有能力，复用 AgentArts、现有模块与适用开源方案。
2. 优先实现、接线和修复核心功能；每项检查必须针对具体风险或验收缺口。
   按交付链共享真实验收，不重复跑全量测试和云调用。
3. 保留本地 Runtime、Policy、ToolGateway 与 Evidence 的信任边界；云失败不静默回退 Local。
4. 16 GB 内存下重型应用和设备验收串行；保留协作者修改和工作树。
5. Potato 连接器只消费公开入口；公共接线按已有授权实施，不扩展为任意模块越权重写。
6. 持续提交小 PR，负责人完成自审和必要检查后按对应授权合并，同行评审按需邀请；分别记录代码、PR、真实模块验收、整体 MVP 状态。
7. 使用剩余可用额度，不使用重置卡，不创建新自动化。缺少凭据或外部依赖时，
   完成其余可独立推进的工作，并明确保留缺项，不降低 MVP 定义。
