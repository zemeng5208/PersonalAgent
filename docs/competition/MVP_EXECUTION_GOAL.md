# 第一版 MVP 执行目标

更新：2026-09-27。来源：产品负责人在当前任务中的直接修订。

## 执行身份与范围

由本任务的 zemeng Agent 本人独立完成实现、接线、返修和必要验证。
旧的“主控只协调、多个开发会话并行”目标作废，不再派发开发或测试给其他会话、
子智能体、Gemini 或 Jev。产品内部的专业 Agent 任务分配仍是必须实现的功能。

第一版 MVP 仍覆盖用户已经约定的全部功能，仅暂不进行 Windows 打包和安装流程。
用户列出的唤醒、连接器、编程、创新和分配任务属于能力示例。
下面由执行 Agent 将这些方向具体化为交付门槛；实现选择、场景与最少必要验收由
执行 Agent 自主确定，不要求用户补写技术清单，也不删除其余已约定需求。

## 必须交付与验收

| 交付链 | 完成条件 |
| --- | --- |
| 文字与桌面 | 实际 Desktop 输入经过真实 AgentArts 返回可用答案；错误、取消和恢复准确；用户能管理任务、能力和授权。 |
| 主动唤醒与语音 | 用户开启后可唤醒并连续交流；云端识别、正常任务执行、播报、打断成立；关闭或撤销立即停止；复用同一授权音频流。目标或事件触发的主动提醒也需真实成立。 |
| Potato 连接器 | 消费已提供的待办/日历、邮件、订阅、通知、研究、天气及约定社交能力；真实发现、参数校验、授权、调用与结果读回。保持 Potatos498 的模块所有权，不重写其实现。各需账号的能力分别留存验收与缺项。 |
| 编程能力 | 在指定工作区读写代码，提供可审查差异，实际应用 patch，执行受限验证命令；不覆盖用户并发修改；结果、冲突和证据真实可见。候选生成不算应用成功。 |
| 创新机制 | 版本化 Fact/Goal/Decision/Plan 和来源；跨会话持续目标；新事实只传播到受影响依赖，输出 KEEP/RECHECK/REVISE 与最小 PlanPatch；用户批准后提交，重启读回且不重复执行；按已约定边界接入 Laya。 |
| 产品内任务分配 | AgentArts 将目标拆解、路由给职责不同的 Agent/工具，完成真实交接、汇总、失败处理、取消和恢复；在产品中可查看分工、状态与证据，不用开发会话委派冒充产品功能。 |
| Windows 与其他约定能力 | 真实电脑状态、受控 Windows 软件操作、知识/Obsidian、偏好记忆、MCP/Skills、管理后台、持续授权与撤销均按约定实现并验收。 |
| 比赛交付 | AgentArts 真实承担构建、编排、部署与必要评估；演示材料中的能力对应代码、部署版本、调用、trace、本地授权、执行和结果证据。 |

## 实施规则

1. 先核对平台和仓库已有能力，复用 AgentArts、现有模块与适用开源方案。
2. 优先实现、接线和修复核心功能；每项检查必须针对具体风险或验收缺口。
   按交付链共享真实验收，不重复跑全量测试和云调用。
3. 保留本地 Runtime、Policy、ToolGateway 与 Evidence 的信任边界；云失败不静默回退 Local。
4. 16 GB 内存下重型应用和设备验收串行；保留协作者修改和工作树。
5. Potato 连接器只消费公开入口；公共接线按已有授权实施，不扩展为任意模块越权重写。
6. 持续提交小 PR，非作者评审后才合并；分别记录代码、PR、真实模块验收、整体 MVP 状态。
7. 使用剩余可用额度，不使用重置卡，不创建新自动化。缺少凭据或外部依赖时，
   完成其余可独立推进的工作，并明确保留缺项，不降低 MVP 定义。
